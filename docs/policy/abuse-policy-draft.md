# 辱骂与仇恨类内容的系统化处理方案（草案 v0.2，2026-10-10，待负责人确认）

上一版只有"针对谁 × 怎么说"两个维度，太粗。这一版从三个问题出发，把方案分成四层：
- **立场**：平台要保护什么、允许什么；
- **事实**：判官回答的客观问题；
- **严重度与处置**：代码按规则表计算；
- **主观性管理**：分歧、标准不统一、判例怎么处理。

## 0. 要解决的三个问题

1. **主观**：同一句话，不同人判断不同。研究把标注分歧的来源分成三类：标注者本身不同（背景、立场），内容或任务本身模糊，同一个人前后不一致【Basile 等，见末尾来源】。另有研究发现，专家标注者之间约三分之一会对一条普通评论是否有毒意见相反【Jury Learning 论文所引】。所以"唯一正确答案"在一部分内容上本来就不存在。
2. **标准不统一**：每个数据集的标签都代表它自己的标准。COLD 把一部分贬低性的刻板印象也算冒犯，换一个数据集可能更宽或更严。直接拿来当标准答案，等于让别人替我们定规则。
3. **平台立场**：要的是可以讨论、允许冲突的环境。合理的争论、对观点和机构的批评、正常的理念冲突应当放行；拦截要有必要、并且和危害相称。

## 1. 立场层：管什么、不管什么

参考联合国拉巴特行动计划的思路："让人不舒服"不等于"有害"，限制言论要有必要且相称【Rabat，见来源】。也参考 Meta 等平台的公开规则：保护的是人和按受保护属性划分的人群，不保护观点和机构；同时有转述谴责、自我指称、政治讨论等例外【Meta，见来源】。

**要管的（按危害从重到轻）：**
1. **威胁、号召伤害或驱赶**：转暴力规则。
2. **去人化**：把人或人群比作动物、病菌、垃圾、非人。
3. **本质化贬低受保护人群**：说某个民族、地域、性别、宗教、残障等人群天生低等、天生是罪犯、道德败坏。
4. **对个人的侮辱**：针对具体的人用脏话、侮辱性称呼。
5. **对个人的贬损嘲讽**：没有脏话，但在贬低一个具体的人。
6. **骚扰模式**：同一账号反复针对同一个人。这一条看的是上下文，不是单条内容。

**不管的（放行）：**
- 批评、反驳、反对某个观点、政策、做法；
- 批评或吐槽机构、学校、公司、城市、作品、产品，包括很难听的批评；
- 没有指向的粗口、感叹；
- 自嘲、圈内人的自我指称；
- 反对偏见的表态；为了谴责或报道而转述别人的话；
- 公共议题上的观点冲突（只要不落到前面"要管的"那几类）。

## 2. 事实层：判官回答的七个问题

不再让判官回答"算不算辱骂"这个整体问题，而是回答一组有固定选项的事实问题。这一做法参考了学术界的分层标注：OLID 依次标"是否冒犯、是否有指向、指向谁"；ToxiCN 标"毒性类型、对象、表达方式（含隐性）"【见来源】。

| # | 问题 | 选项 | 谁来回答 |
|---|---|---|---|
| D1 | 有没有明确的攻击对象？ | 有 / 没有 / 指向含糊 | 判官 |
| D2 | 对象是什么？ | 对话中的具体个人 / 公众人物 / 按受保护属性划分的人群 / 其他人群（职业、学校出身、粉丝群体等）/ 机构、地方、作品、产品 / 观点、政策、做法 / 说话者自己 | 判官 |
| D3 | 如果是人群，按什么属性划分？ | 民族种族 / 地域 / 性别 / 宗教 / 残障或疾病 / 性取向 / 年龄 / 其他 / 不适用 | 判官 |
| D4 | 用了什么方式？（按严重度排序，取最重的一项） | 威胁或号召伤害 / 去人化 / 本质化贬低 / 侮辱性称呼或脏话 / 贬损嘲讽 / 不带贬低的以偏概全 / 批评或反对 / 都没有 | 判官 |
| D5 | 怎么表达的？ | 直白 / 隐晦（谐音、缩写、暗语、阴阳怪气）/ 转述或引用 / 反讽 | 判官 |
| D6 | 说话者的立场？ | 赞同这种偏见或攻击 / 反对偏见 / 中立讨论 / 自嘲或圈内自称 / 看不出 | 判官 |
| D7 | 上下文 | 回复的是谁、是不是在回击先前的辱骂；同一账号有没有反复针对同一人；当前场景 | **agent 用工具查**，判官看不到 |

说明：
- D1–D6 每一项都比"算不算辱骂"更接近客观事实。即使还有分歧，也能定位到具体是哪个维度有分歧。
- D3 的"受保护属性"按 Meta 的做法处理"代理词"：用来暗指某个受保护人群的词（比如某些地域蔑称），按该人群对待。
- D7 需要线程、账号历史这些上下文，这正是 agent 要去查的东西。它把"为什么需要 agent"落到了具体规则上。

## 3. 严重度与处置层：代码查表，比例相称

结论不由判官直接给，而是由代码按下表算出严重度，再按场景对应到处置。

### 3.1 基础严重度（由 D2 × D4 决定）

| 对象 \ 方式 | 威胁 | 去人化 | 本质化贬低 | 侮辱、脏话 | 贬损嘲讽 | 以偏概全 | 批评、反对 |
|---|---|---|---|---|---|---|---|
| 具体个人 | S4 | S4 | S3 | S3 | **S2** | S0 | S0 |
| 公众人物 | S4 | S4 | S3 | S2 | S1 | S0 | S0 |
| 受保护人群 | S4 | S4 | S3 | S3 | S2 | **S1** | S0 |
| 其他人群 | S4 | S3 | S2 | S2 | S1 | S0 | S0 |
| 机构、地方、作品 | S4 | S0 | S0 | S0 | S0 | S0 | S0 |
| 观点、政策 | – | S0 | S0 | S0 | S0 | S0 | S0 |
| 自己 | – | S0 | S0 | S0 | S0 | S0 | S0 |

D1 为"没有对象"时一律 S0（无指向的粗口）。

### 3.2 修正项

| 条件 | 修正 | 理由 |
|---|---|---|
| D6 = 反对偏见，或 D5 = 转述且 D6 不是"赞同" | 降到 S0 | 谴责、报道、反对偏见是例外（Meta 也这样处理） |
| D6 = 自嘲或圈内自称 | 降到 S0 | 自我指称 |
| D6 = 看不出，且 D5 = 隐晦或反讽 | 严重度不变，但**标为"需要上下文"** | 隐晦表达本身不减轻危害，但靠一句话判不准，交给 agent |
| D7：在回击先前针对自己的辱骂 | 降一级 | 相称原则：先挑衅的一方更重 |
| D7：同一账号反复针对同一人 | 升一级 | 骚扰模式 |
| 对象是机构，但实际在借机构骂其中的人（比如"那个学校出来的都是废物"） | 按"其他人群"重算 | 防止借批评机构的名义攻击人 |

### 3.3 处置阶梯（按比例，不一刀切）

| 严重度 | 默认处置 | 说明 |
|---|---|---|
| S0 | 放行 | 包括尖锐的批评和争论 |
| S1 | 放行，进抽查样本 | 争议地带，不靠拦截兜底 |
| S2 | 限流或折叠（对应现有的 limit） | 不删，但降低曝光；比如"请你闭嘴，没人想听你废话" |
| S3 | 下架（takedown） | 侮辱个人、本质化贬低人群 |
| S4 | 下架，并标记账号 | 去人化、威胁；威胁转暴力规则 |

场景可以整体调一档，写在 `config/scenes.yaml` 里。比如游戏弹幕对粗口更宽，新闻评论对人群贬低更严。

## 4. 主观性管理层

### 4.1 分歧按来源分别处理

| 分歧来源 | 表现 | 处理 |
|---|---|---|
| 规则没写清 | 同类内容反复出现分歧 | 负责人裁定，裁定结果写成判例，规则版本加一 |
| 内容本身模糊 | 多个标注者在某个维度上意见不一 | 标为"争议"（S1 或"需要上下文"），不强行判对错 |
| 立场不同 | 某些人群看法系统性不同 | **明确由谁的标准说了算。**Jury Learning 的思路是把"谁的意见算数、各占多少比重"写成明确的设计选择，而不是悄悄用多数票【见来源】；我们这里由负责人确认规则来定，并写进文档 |

### 4.2 标准答案怎么产生

1. **在事实维度上标注，而不是直接标结论**：每条内容的 D1–D6 由至少两个不同来源的模型独立标注（不用 Jev，避免自己考自己）。两边一致就采用，不一致的交负责人。结论由代码按第 3 节查表得出。
2. **保留分歧本身**：记录每个维度上的标注分布（软标签），不只留多数票。研究显示，有分歧的样本不应丢弃，处理得当反而有用【见来源】。
3. **量出天花板**：计算各维度标注者之间的一致率。判官的准确率不可能、也不应该被要求超过人和人之间的一致程度。
4. **评测分开报告**：明确项看对错；争议项看"有没有被送到正确的路径"（放行抽查或交给 agent），不算错。

### 4.3 外部数据集：翻译到事实维度，而不是结论

每个数据集写一张对照表，把它的类别对应到本方案的维度。对应不上的条目，按 4.2 的流程重新标注。原始标签和本方案标签的成绩分开报告，不同数据集也不混算。

以 COLD 为例：

| COLD 标签 | 对应到本方案 |
|---|---|
| 安全 · 其他 | 多数是 S0 |
| 安全 · 反偏见 | D6 = 反对偏见，S0 |
| 冒犯 · 攻击个人 | D2 = 具体个人；具体严重度看 D4，可能是 S0（批评）到 S3 |
| 冒犯 · 攻击群体 | D2 = 受保护人群；看 D4：本质化贬低是 S3，以偏概全是 S1，批评是 S0 |

所以 COLD 的"冒犯"不能直接等于"拦截"。前面核查的 99 条漏放里，有 63 条被第二意见判为中性讨论、反偏见或反讽，按本方案很可能是 S0 或 S1，本来就该放行。

### 4.4 判例库

- 负责人对争议的裁定写成判例，带上 D1–D7 的取值和结论。判例和规则一起进版本，规则版本号随之变化。
- 契约测试从判例里取；新规则上线前，所有判例的结果要么不变，要么是有意改变。
- 申诉改判的案例自动成为判例候选，并按"对象 × 方式"的格子统计改判率。改判率高的格子，说明规则或阈值有问题。

| 环节 | 改动 |
|---|---|
| 规则文件 | `rules/ABUSE-001.yaml` 增加维度定义、严重度表、修正项、场景调整、判例、数据集对照表；仍由 `rules_ver` 固定版本 |
| 快判（G） | 一次 Jev 调用回答 D1–D6（Jev 一次调用可以问多个问题【实测】）；代码查表得严重度。D6 看不出且表达隐晦，或对象含糊时，转"需要上下文"进 agent |
| agent（W） | 初始任务带上 D1–D6 的结果和"缺的是 D7 的哪一项"；工具按回复关系取上下文、查同账号对同对象的历史 |
| 校准 | 按事实问题分别校准（这也解决了现在校准桶键没有问题标识的缺陷） |
| 疑似分流 | "需要上下文"进 agent；"系统不可用"（缺校准、判官故障）直接转人工；"S1 争议"放行加抽查 |

## 6. 风险和反面意见

- **错误会累积**：七个问题各对 90%，全对的概率只有约 48%。缓解办法：结论主要由 D2 和 D4 决定，其余是修正项；按维度分别测准确率，找出最弱的一环。
- **事实维度本身也有主观性**："贬损嘲讽"和"批评"、"以偏概全"和"本质化贬低"的边界仍然要靠定义和判例来划，拆开问并不能消除主观性，只是把它暴露出来、定位到具体维度上。
- **没被证明一定更好**：拆开问是否比整体一问更准、更稳，需要在案例池上对比（整体一问 vs 拆开问），结果可能对拆开问不利。如果不利，就保留整体一问，只用这套维度来组织规则文档和判例。
- **成本**：问题从 3 个增加到 6 个以上，单次调用的 token 增加（现在约 1,400 输入 token）。要实测延迟和费用。
- **过度设计**：第一版只做辱骂这一条规则，其他规则等这条验证完再说。

### 6.1 初测结果（2026-10-10，29 条 COLD 抽样）：照现在的写法，拆开问不可用

- glm-5.3-flash 和 deepseek-v4.1-flash 各跑一遍：三方都认定的明显冒犯（Jev 打 1.0 或 0.935 分），两个模型都有拆成"立场：反对偏见"的，按修正项直接降到 S0 放行。deepseek 把 29 条里的 14 条都标成了"反对偏见"。
- 同一个模型跑两遍，也有条目的严重度不一样。
- 对比：上一轮直接问"按 COLD 定义算不算冒犯"，明显冒犯 glm 认对 98%。
- 两个不同模型犯同样的错，所以问题在拆解的写法，不在模型：
  - "反对偏见"的定义太宽，模型只要看到在反驳别人就选它；
  - "反对偏见 → 降到 S0"这条修正太强，一题选错，结论就整个翻掉；
  - COLD 的话题本来就是种族、地域、性别，模型却常把对象标成"其他人群"，对象类型的定义也不够清楚。
- 下一步要改的方向（未做）：
  1. "反对偏见"改成必须明确谴责针对某个群体的偏见，并配正反例；
  2. 修正项加一致性约束：如果 D4 是对个人的侮辱，D6 就不能是反对偏见；
  3. 或者改成混合方案：保留整体的"是否违规"问题做主判断，维度只用来定严重度、处置和写理由。

  这三条都要在案例池上和"整体一问"对比后再定。

### 6.2 第二次测试（同一批 29 条）：改成按片段拆解后

改动：
- 按片段拆：先列出评论里每一处"对某个对象的评价或攻击"，每处单独标对象、方式、表达、立场；严重度取最重的一处。
- 例外只作用于本片段：如果某一处在侮辱、本质化贬低或去人化，它就不能同时算"反对偏见"。
- 收紧定义，配正反例：
  - "反对偏见"只指明确谴责或纠正针对某个人群的偏见，"反驳某人""骂持偏见的人"都不算；
  - "受保护人群"明确包括"某地人""女的"等称呼。

结果【实测，deepseek-v4.1-flash 和 glm-5.3-flash 各标一遍，glm 有 2 条输出解析失败】：

| 检查 | 第一次（整句选一个） | 第二次（按片段） |

| 三方都认定的明显冒犯（第 252、3301、4040 行） | 3 条里 2 条被判成放行 | 全部 ≥ S2（S4 / S3 / S2），两个模型一致 |
| 负责人看过的第 305 行（山大） | 放行 | 放行，两个模型一致 |
| 两个模型的严重度完全一致 | 未测 | 27 条里 22 条 |
| 差距不超过一级 | 未测 | 27 条里 26 条 |
| 处置大类一致（放行 / 限流 / 下架） | 未测 | 27 条里 26 条 |
| 片段被标为"反对偏见"的比例 | deepseek 29 条中 14 条整句 | deepseek 66 个片段中 20 个，glm 66 个中 11 个 |

还没解决的：
- **第 1 组的 8 条**（Jev 放行、上一轮 glm 整体判为冒犯）在新方案下大多是 S0 或 S1，和 Jev 一致、和上一轮 glm 不一致。哪个对，需要负责人看原文判断。
- **第 3477 行**：两个模型差了两级（S2 和 S4）。
- **一致性检查一次都没触发**：被标成例外的片段，方式都不是侮辱或贬低。所以"反对偏见"是否仍然用得太宽，要靠负责人看文档里的片段来判断。

- Jev 交给 agent 的 281 条：我们 56% 放行，44% 处理。

怎么读：
- **29 条时的高一致性是小样本的偶然。**放大后，两个模型在"对象""方式""立场"这三个事实维度上各自只有 50%–60% 一致；片段怎么切也一半对不上。拆开问没有消除主观性，只是把它摊到了各个维度上。
- **"反对偏见"仍是最大的分歧来源。**deepseek 触发例外的条数比 qwen 多六成。另外，deepseek 有 23 个片段的立场填了选项以外的词（例如"攻击"），格式约束也要加强。
- **和 Jev 的关系**：在两个模型都一致的条目上，Jev 的放行和拦截与本方案高度吻合；分歧集中在 Jev 交给 agent 的那部分，以及两个模型自己意见不一的那部分，也就是本来就模糊的内容。
- **还没比较的**：两个模型直接整体问"该放行、限流还是下架"，一致率是多少。如果整体问一致率也只有七成上下，说明这批内容本身就模糊；如果明显更高，说明拆开问反而引入了噪声。

负责人阅读文档（含原文，不进 git）：开发机 `data/review/decompose-disagreements-2026-10-11.md`，共 31 条：
- 9 条：两个模型都说该处理，Jev 却放行；
- 2 条：Jev 拦截，两个模型都说放行；
- 20 条：两个模型差两级以上（从 145 条里随机抽）。
