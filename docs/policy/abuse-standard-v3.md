# 辱骂类统一标注标准 v3（草案，2026-10-08）

> **写法说明（2026-10-08 起统一）**：本文只记录做了什么、为什么这么做、测得的数字，以及考虑不够全面的地方。文中实验数字和看法均**仅供参考**（样本、设置、标注方式都有限），不作为结论；结论由审查方判断。日期按美国纽约时间（America/New_York）。

目标（负责人 2026-10-08）：同一条评论，不同标注者（两个不同家族的模型，以及人）按这份标准判，**二分类（违规 / 不违规）一致率 ≥ 90%，而且每一类（辱骂、数据集安全样本、日常评论、自建难例）都要各自 ≥ 90%**，不能靠容易的类把总数拉上去。先做辱骂类，营销类照同样方法后做。

范围和 v2 提示词（`docs/policy/abuse-prompt-v2-draft.md`）相同：V4 威胁；V3 去人化、贬低受保护人群、用脏话骂具体的人或受保护人群；V2 羞辱具体的人本身、嘲讽受保护人群。**不改规则，只改问法**。

## 1. 为什么以前判不一致【实测，deepseek-v4.1-flash 对 qwen3.8-flash，COLD 抽样】

| 现象 | 数字 |
|---|---|
| v2（整体判断，三选一）一致率 | 77.0%（538 条）；其中"不确定 / 允许"互相分歧 65 条，占 12% |
| 拆问题（按片段列对象、方式、表达、立场）级别一致率 | 59.5%（996 条） |
| 拆问题里"立场"这一题 | 一致 50.0%；最大分歧"中立讨论 / 看不出" 122 条 |
| "方式"这一题 | 一致 55.1%；"批评反对 / 贬损嘲讽" 92 条，"本质化贬低 / 贬损嘲讽" 67 条 |
| "对象"这一题 | 一致 60.4%；"其他人群 / 受保护人群" 118 条 |
| 片段数 | 两家拆出的片段数经常不同（3 对 2 有 151 条），最后取最重片段，一处分歧就翻转整条 |

根因：
1. **有"看不出 / 不确定"这种出口**，标注者在边界上随意落到不同出口；
2. **问的是心理状态**（立场、意图），原文里看不到，只能猜；
3. **问的是程度**（批评 / 贬损 / 本质化贬低是一条连续的线），切点各人不同；
4. **先拆片段再取最重**，把小分歧放大。

## 2. v3 的问法（`rules/prompts/abuse-facts-v3.txt`）

原则：
- 只问**原文里看得见**的东西，每题都有"算 / 不算"的例子；
- 每题只答"是 / 否"，**拿不准答"否"**（开放讨论立场：存疑放行）；
- 整条评论一起答，不拆片段；
- 标注者不下结论，**标签由固定的表算出来**（`scripts/lib/abuse-v3.ts` 的 `labelV3`）。

| 题 | 问什么 | 命中 |
|---|---|---|
| q1 | 用脏话或侮辱性称呼称呼 / 形容具体的人或受保护人群 | V3 |
| q2 | 把人比作动物、病菌、垃圾等 | V3 |
| q3 | 威胁、号召伤害或驱赶 | V4 |
| q4 | 断言受保护人群整体有负面品质或低人一等 | V3 |
| q5 | 拿受保护人群的身份当贬义词或笑料 | V2 |
| q6 | 贬低具体的人本身（智力、人品、长相、身份），而不是他的言行作品 | V2 |
| q7 | 上面命中的部分是被引用来反驳、谴责，或被否定 | 清除全部，判允许 |

计算：q7 为是 → 允许；否则取命中的最重一级；都没命中 → 允许。

## 3. 怎么验证（试标）

- 从 2 万条的**开发集**里分层抽 400 条：辱骂 30%、数据集里的安全样本 30%、自建难例 20%、日常评论 20%（`scripts/pilot-abuse-standard.py sample`）；
- 同一批条目，deepseek 和 qwen 各按 v2 和 v3 标一遍（`scripts/pilot-abuse-standard.ts`），比较：二分类一致率、kappa、每一题的一致率、按来源的一致率、两家一致时和原始标签的吻合度；
- 哪一题一致率低就改那一题的说法和例子，再测；直到二分类一致率 ≥ 90%；
- 达标后仍不一致的条目交负责人裁定，裁定写成判例补进例子。

## 4. 试标结果

### 4.1 第一轮（416 条，开发集分层抽样；deepseek-v4.1-flash 对 qwen3.8-flash；未设 temperature）【实测 2026-10-08】

| 二分类一致率 | 总体 | 辱骂 | 数据集安全样本 | 日常评论 | 自建难例 |
|---|---|---|---|---|---|
| v2（整体判断） | 92.5%（kappa 0.77） | 80.3% | 96.7% | 98.7% | 100% |
| v3（7 道是非题） | 92.7%（kappa 0.75） | 80.0% | 98.3% | 98.7% | 96.4% |

- 辱骂类 v2 80.3%、v3 80.0%，都低于 90% 的目标；其他三类在 96%–100%。
- qwen 在 v3 上有 20 条请求失败，集中在辱骂类（ChineseHarm 只成功 17/26）；抽查 5 条，4 条是中转站 502。原因未查清（一个猜测是示例脏话加原文触发了上游过滤，未证实）。缺失的条目可能偏难，v3 的数字可能因此偏高。
- v3 两家判反的 29 条里，涉及 q5（拿人群身份取笑）10 条、q1（脏话）9 条、q4（人群整体负面）9 条。
- 两家一致时，和数据集原标签不同的约 12%。可能的原因是数据集标准和本平台规则不同，没有逐条核对。
- Jev 用同样 7 道是非题（概率 ≥ 0.5 算"是"）：和 qwen 一致 91.4%，和 deepseek 86.5%；判违规比例 25.7%（两家 17–20%）；q1、q5、q7 答"是"的次数多于两家。0.5 这个切点没有校准过。

### 4.2 第二轮（300 条辱骂类）【实测 2026-10-08，仅供参考】

目的：分开两种分歧——同一模型问两遍答案就会变（随机），还是两家理解不同（系统性）。做法：
- v3.1：把示例脏话改成描述性说法（修 502），reason 不再要求摘抄原文；
- temperature 设 0 和不设各跑一遍，每种问两遍，测每家"自己和自己"的一致率；
- 只用辱骂类：300 条（含第一轮的 132 条，其余从开发集按来源分层补抽，`data/eval/pilot-abuse-ids.txt`）。

结果（二分类一致率，辱骂类）：

| | 不设 temperature | temperature = 0 |
|---|---|---|
| deepseek 自己问两遍 | 81.3% | 84.7% |
| qwen 自己问两遍 | 100%（281 条） | 100%（283 条） |
| Jev 自己问两遍 | 97.7% | 98.0% |
| deepseek 对 qwen（两遍分别） | 79.0% / 78.3% | 79.5% / 79.9% |
| deepseek 对 Jev | 75.3% / 76.3% | 74.3% / 74.3% |
| qwen 对 Jev | 79.4% / 76.3% | 78.4% / 78.6% |

判违规比例：deepseek 约 53%，qwen 约 56%，Jev 约 63%。各题一致率在 `scripts/pilot-abuse-standard.py score` 的输出里（q1 约 78%–85%，q3 约 95%–96%）。

不足：
- qwen 两遍完全一样；负责人确认中转站不缓存相同请求；
- deepseek 在 temperature = 0 时仍有约 15% 两遍不同；一个可能的原因是这个渠道不支持设置 temperature（负责人提出），未验证；
- qwen 每轮仍有 5–19 条请求失败，失败条目每次不完全相同，原因没查清；
- 只用了辱骂类 300 条，只有 deepseek 关思考这一种设置，没有人工标注作对照。
