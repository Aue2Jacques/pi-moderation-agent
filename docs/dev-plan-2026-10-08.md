## 1. 原则

- **一个裁决入口**：线上 G/W、人审页、离线评分都经过同一个策略入口（`packages/policy` 的 `decide`），不在脚本里另写一份"差不多的逻辑"。原始分数的 AUC 和校准曲线可以单独算，"放行多少、转人工多少、执行什么动作"必须经过这个入口。
- **已知问题先变成回归测试**：每个修复都带一个在当前版本上会失败的测试；费用类测试的期望值用独立构造的请求数和单价算，不调用被测函数自己算。
- **harness 约束随功能一起做**：权限、版本、预算、证据归属、停止条件和功能同时实现；缓存、上下文压缩、调度优化等放到有数据之后。
- **实验可重算**：同一批已保存的输出重新评分，结果必须一样；重新调用远程模型时，协议相同，结果的波动如实报告。
- **不再增加旁路实验**：新的判官、数据集、训练在第 ④ 阶段之前暂缓（正在跑的 Kaggle 任务让它跑完）。

### 2.2 裁决语义

- **规则 × 例外 → 处置**（**已做 2026-10-08**）：EX-QUOTE 删除后，ABUSE 只剩事实问题；"反偏见"写进规则定义。规则文件（v2）、题面、契约夹具同步更新；c5 期望改为"放行"。真实 Jev 重录后契约 6/7：c2（边界辱骂句）均值 0.895，低于未校准的 0.90 拦截线（仅供参考；按事先约定不为让它通过而重录）。用 COLD / ChineseHarm 标签做温度校准的尝试见 `reports/2026-10-08-calibration-with-public-labels.md`：辱骂题 T = 7.24，校准后辱骂基本不会自动拦截，契约变成 5/7，因此未采用。负责人 2026-10-08 决定 c2 先保持现状，等有本平台标签再校准、定阈值。
- **多规则合并**：动作取最重；裁决只引用支持这个动作的规则，其他命中记在理由里；`allowedActions` 只给这一个动作。
- **注入配对测试（快判层，已做 2026-10-08）**：开发集 201 对，加后缀后判断改变：违规原句 19/102（其中变为放行 7），正常原句 14/99（其中由放行变为疑似 / 拦截 10）；同一句重问的对照分别为 2 和 1（仅供参考，见 `reports/2026-10-08-injection-pairs-fastpath.md`）。负责人 2026-10-08 选择在快判加注入检查题（已做）：同样 201 对，违规内容被后缀带成放行由 7 变为 0；带后缀的内容 95.5% 被检查题命中、转给 agent；不带后缀的原句 402 次询问命中 0 次（仅供参考，同一报告第二轮）。c5 的期望随之改为"转 agent"（release）。agent 层配对测试在第 ② 阶段做。
- **疑似原因分三类**，写进审次，agent 一开始就能看到：
  - 缺上下文（中间带、需要看回复对象或历史）→ 进 agent，告诉它要核验什么；
  - **系统不可用**（缺校准、判官不可用、规则包取不到、能力不支持）→ **不进 agent**，直接转人工或降级，不耗预算；
  - 证据已全仍有争议 → 有限复核，没有新信息就停。
- **双确认**改成可开关的策略，开、关都在案例池上跑（负责人 10-07 决定）。
- **未知规则编号、缺配置**不能默认成较轻处置，也不能和"业务上允许放行"混为一类。

## 3. 第 ② 阶段：最小 harness 闭环

验收：一批案例的输入、证据、终态、费用和报告都能重跑；A、C 两组在同样条件下各跑一遍，报告包含失败和转人工，不从分母里拿掉。这一步是功能试验，不用来宣称效果显著。

- **案例池 60–100 条**：一半自写、一半来自公开数据（负责人 10-07 决定）。四类：上下文能改变结论；历史是诱饵；确实缺证（应转人工）；普通对照。内容、线程、账号历史、证据边界、预期结果、标签来源一起冻结；ID 不透明。
- **标签分三种来源，分开存**：原始人工标签（数据集自带）、模型共识标签（deepseek + qwen）、负责人裁定标签。两个模型一致只算"模型共识"，不当作独立人工真值。
- **agent 任务说明**：初始任务带上为什么疑似、卡在哪条规则、待核验项、能取哪些证据、剩余预算和截止。判官工具返回"当前能支持哪些处置、还缺什么条件"，不再让模型靠提交被拒来摸索。同样的证据请求不重复做。缺证时停止并转人工。
- **A/C 对比**：A = 固定取证（每次查线程、历史、复判），C = agent 自己决定查什么。同一案例池、主模型、规则包、证据环境、预算、截止和裁决入口。报告：对标签的正确、错误、合理转人工、系统无法完成；自动完成覆盖率；工具调用数；全部物理请求的费用；时延。结果对 C 不利也如实写。
- **校准**：原定用公开数据集自带的标签拟合（负责人 10-07 决定），拟合数据和案例池不重叠；没有校准文件的桶按"系统不可用"处理。2026-10-08 用 COLD / ChineseHarm 试过一次（见上面的报告），辱骂题温度过大、不能直接用；校准数据的标签来源需要重新定（待负责人定）。

## 5. 第 ③ 阶段：补齐功能

每项都要从真实入口走通正常路径和至少一条失败路径（接管、版本变化、降级）。

- **图片审核**：最小通道——图片实际送达所选模型，结果归到正确审次，进入同一处置链；不支持的类型明确降级。线上接口待负责人定。
- 长文本、暴力类规则（目前没有数据覆盖，先定规则和少量案例）。
- 人工与申诉：至少一批任务真正经历人工领取、裁决、申诉重审、下游状态更新。
- 规则发布：最小影子检查、有限灰度、回退；旧审次继续用旧版本。
- 反馈回流：反馈产生候选配置，经检查后批准或拒绝，不直接改线上阈值。

## 6. 第 ④ 阶段：扩大实验与性能

- 两万条完成正式切分和本平台标签后，判官（Jev、开源判官）只在测试集上出成绩；"比商用服务好"作为挑战目标，有条件时再比。
- 性能：先找一个能稳定处理的负载 R，做三项检查——稳定负载（队列不持续增长，质量、完成率、超时、费用一起报）、短时超载（背压或明确降级，恢复后能排空、不丢、不无限重试）、故障后恢复（不突破准入限制）。接入、快判完成、完整审核完成三种速度分开报；排队时间和执行时间分开报。循环使用测试数据压测时，区分首次处理、缓存命中、重复事件幂等。
- 6:4 是评测构成，不是真实流量；分别报告分层评测分布和几种明确假设的运行分布。
- 拿到这些数据后，再按瓶颈决定是否做缓存、减少重复取证、压缩上下文、批处理、并发调整或换模型。
