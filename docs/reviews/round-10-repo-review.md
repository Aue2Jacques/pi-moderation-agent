## Standards

1. **[P1] 单实例锁可能同时被两个活进程取得。** A 创建锁文件、尚未写入 PID 时，B 会把空文件当成陈旧锁删除；最后两个进程都返回成功。已复现 `bothAcquired=true`，这破坏了 durable 存储只能由一个进程持有的前提。应使用实际的操作系统互斥锁。（`packages/worker/src/flock.ts:15`）
2. **[P2] 受限数据库没有落实文档要求的 `0600` 权限。** 默认 `umask 022` 下，数据库、WAL、SHM 实测均为 `0644`。（`packages/core/src/db.ts:16`）
3. **[P2] 工具恢复绕过费用准入检查。** 费用门仅在 `beforeTool`，恢复执行经过的 `guard` 没有费用检查。复现中预算为 200 微元，恢复前已计入 200，恢复仍发出新请求，累计到 680 后才转人工。问题是**预算已耗尽仍准入新请求**，不是要求撤销已经发生的费用。（`packages/worker/src/extension.ts:48`）
4. **[P2] 导入错误会把输入片段打印进日志。** `String(error)` 会保留某些 JSON 解析错误里的原文预览。应直接把 Error 交给脱敏器，配合行号定位。（`packages/core/src/intake-cli.ts:28`）

## Spec

1. **[P1] 中止后的重启窗口会让审核"有租约、无任务"。** 旧执行已被中止、尚未重新提交时重启，代码看到旧 `submission_id` 非空便跳过提交。完整 Worker 复现得到：`attempt=2`、`investigating`，但模型请求和活任务均为零，仍占着并发槽，直到超时才转人工。（`packages/worker/src/worker.ts:115`）
2. **[P2] 主模型重试费用少计，却标成已结算。** 同一个生成任务重试时，账本只保留首次用量；宿主收尾再用它覆盖 Pi 的累计用量。复现中两次物理请求的模拟费用为 1565 微元，最终记录只有 556，状态却是 `settled`。（`packages/worker/src/worker.ts:235`）
3. **[P2] 执行库没查到，对账仍能显示成功。** 明确指定不可达的 W，脚本仍可退出 0、返回 `ok:true`。核心检查也漏掉缺失会话、没有任务的活动审核等情况。（`scripts/reconcile.ts:21`）
4. **[P2] 七天历史总计实际上只统计最近五条。** 查询先 `LIMIT 5`，再从这五条计算总数。（`packages/worker/src/extension.ts:217`）
5. **[P2] "前后各三条"实际是距离最近的六条。** 已复现返回前六、后零。（`packages/worker/src/extension.ts:192`）
6. **[P1] 同时命中辱骂和营销规则，会卡在快判重试。** 策略选择 `takedown`，却把只允许 `limit` 的营销规则一起提交；权限门正确拒绝，G 随后重新调用判官。两轮复现后仍为 `preprocessed`、零裁决，且没有有限重试后的转人工出口。应修正动作与支持规则的对应关系，不能放宽权限门。（`packages/policy/src/engine.ts:19`）
7. **[P2] 更新规则后，旧的人审任务无法提交。** 人审接口使用 G 当前的规则包，而审核固定的是旧版本。真实本地 HTTP 复现返回 `409 E_VERSION_MISMATCH`。（`packages/gateway/src/http.ts:104`）
8. **[P2] 快判完成后，其费用从仪表盘里消失。** 统计以 `review_id IS NULL` 识别快判费用，但完成快判时会给调用绑定审核 ID。复现中判官账本记录 100 微元，仪表盘总成本和每千条成本均为零。对账脚本也采用了同样口径。（`packages/gateway/src/gateway.ts:141`）

对 README 已披露的问题：未拟合校准、图片未实现、没有效果数字已诚实披露；但默认 strict 路径大量转人工，不能用 identity 模式联调结果证明正式审核能力。明显句子 13/50 是单条输入的重复实验，不是召回率，不宜为提高这个数字直接降阈值。注入式文本被放行不自动等于模型执行了注入，应先确定契约要求什么。契约只录一次：固定录制适合检验业务代码，重复真实调用适合测模型波动，不要反复重录挑一次通过。

从找工作的角度，工程深度已经成立，但证据链还没完成。建议下一阶段：1）修复单实例锁、恢复停滞和多规则快判失败；2）修复对账、费用及证据读取，补回归；3）确定规则契约含义，完成真实校准；4）跑固定工作流与 Agent 的对照，报告完整成本和自动完成覆盖率。
