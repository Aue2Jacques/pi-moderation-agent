# 数据、清洗与评测做法说明（供审查，2026-10-08）

**写法说明**：本文只写我们做了什么、为什么这么做、测出来的数字、以及考虑得不够的地方。所有实验数字**仅供参考**：样本量有限、标注者是模型、很多设置只试了一种，不足以支撑结论。结论请审查方根据数据自行判断。日期按美国纽约时间。

相关文件：方案 `docs/eval-dataset-plan.md`，标注标准 `docs/policy/abuse-standard-v3.md`，全盘状态 `docs/project-status-2026-10-08.md`。

## 1. 参考了哪些标准规范

我们在找"内容审核"和"数据清洗 / 标注"有没有可以照着做的标准。下面列出查到的、实际读到的内容和我们怎么用。**没有找到专门规定"用户评论 / 图片违规内容审核"怎么做的国家标准**；下面的国标针对的是生成式 AI 的训练数据和生成内容，我们只借用它们的做法作参照，不代表本项目适用或符合这些标准。

| 规范 | 读到了什么（原文条款） | 我们怎么参照 | 没读到 / 不确定的 |
|---|---|---|---|
| **GB/T 45674—2025《网络安全技术 生成式人工智能数据标注安全规范》**（2025-04-25 发布，2025-11-01 实施；读的是国标原文 PDF） | 第 6 章：标注规则应至少包括标注目标、数据格式、标注方法、质量指标；要有正反例；要有"不恰当或错误标注的识别方法及参考示例"；要有核验方法。第 8.1 条：核验由**未参与当前批次标注的人员**随机抽样，或算法检测后再人工抽样；问题要纠正或重标，并逐条记录原标注、纠正后标注、人员和时间；安全性标注每种风险宜不少于 200 条。第 8.3 条：未通过核验的超过该批次 5% 时，整批作废 | 标注标准写成"目标 + 题目 + 正反例 + 质量指标（两家一致率 ≥ 90%）"；分歧交负责人裁定并记成判例；标注记录保存模型、提示词版本、时间 | 我们的"标注者"是两个大模型，不是人；没有独立的人工核验员；没有按 5% 作废规则执行 |
| **GB/T 45654—2025《网络安全技术 生成式人工智能服务安全基本要求》**（读的是 CSET 英文译本） | 附录 A：31 类安全风险，其中 A.2 歧视（民族、信仰、国别、地域、性别、年龄、职业、健康）、A.4 侵害他人权益（含损害他人名誉、荣誉）。附录 B：关键词库不少于 1 万个、每周更新；生成内容测试题库不少于 2,000 题，A.1 / A.2 每类不少于 50 题；训练数据人工抽检每种模态不少于 4,000 条、合格率不低于 96%，技术抽检不少于 10%、合格率不低于 98%；生成内容抽检合格率不低于 90% | 受保护人群的列表参照 A.2；测试集规模（2,000–4,000 条，负责人定）与题库、抽检规模同一量级 | 只读了译本，没有逐条对照中文原文；它针对生成式 AI，用到用户评论审核上是我们的类比 |
| **《网络信息内容生态治理规定》**（网信办，2020） | 第六条列违法信息，第七条列不良信息（含侮辱、诽谤、歧视等），适用于文字、图片、音视频 | 规则的总范围参照它（此前已在规则草案中引用） | 只到条款级，没有可执行的判定细则 |
| **《网络短视频内容审核标准细则》**（中国网络视听节目服务协会，2019 年发布，2021 年修订，21 类 100 条） | 只读到新闻报道里的类别数和部分条款，**没有读到全文** | 图片审核的类别划分候选参照 | 全文未读，不能引用具体条款 |
| **ISO/IEC 5259 系列**（AI 与分析的数据质量，2024–2025） | 只读到各部分范围：第 2 部分是数据质量模型与度量，第 4 部分是数据标注流程框架 | 作为"数据质量要报告哪些维度"的参照 | 正文收费，没读到具体度量 |
| **云厂商图片审核分类**（AWS Rekognition 三级标签体系，2024 年 2 月起；腾讯云图片审核场景） | AWS：一级类含露骨裸露、性暗示、暴力、令人不适、毒品、烟草、酒精、赌博、粗鲁手势、仇恨符号等，三级层级；不设置最低置信度时默认返回 ≥ 50% 的标签 | 图片功能的类别和阈值设计参照 | 厂商规格，不是标准 |

另外参照了一个团体标准的说法（不同标注人员一致率 ≥ 95%）；它不是国标，我们也没有读到它的全文，只作背景。

## 2. 数据组成

做法：从 8 个公开数据集 + 5 份日常评论语料 + 自建部分拼出 20,232 条（违规 8,086 / 正常 12,146）。详细配额见 `docs/eval-dataset-plan.md` §4。

为什么：只用 COLD 一个数据集覆盖面窄（只有偏见话题，"攻击个人"只有 288 条，没有营销引流）；负责人要求来源尽量多、要有日常评论、规模 2 万、正常与违规 6:4。

不足：
- 暴力威胁、博彩、色情没有覆盖（前者没有成规模的中文公开数据，后两者不在当前规则范围）；
- 多数公开数据集是非商用许可，只能评测，不能再分发；
- 日常评论语料原本是情感标注（好评 / 差评），我们默认它们"不违规"，这个假设只靠两个模型筛过一遍；
- 6:4 的配比远高于真实流量的违规比例，算"误拦占比""交给 agent 的比例"时需要重新加权，目前还没做。

## 3. 清洗

### 3.1 格式统一

做法：所有来源过同一套规则（`scripts/lib/normalize.py`）：HTML 符号还原、繁转简、去掉链接、@用户名、"回复@某人："、转发链、`[表情代码]`、`#话题#`、unicode 表情，合并空白，只留 2–200 字。变体和注入在清洗之后再加。

为什么：各来源的格式痕迹和标签绑在一起（例如微博评论 100% 带表情代码且都是正常样本，Matters 广告 45% 是繁体且都是违规样本），判官可能学到"认出处"。负责人要求全部抹除、越简单越好。

怎么测的：只用长度和 11 个格式特征训练逻辑回归，5 折交叉验证，看它猜二分类标签的 AUC（越接近 0.5，格式越不漏标签）。

数据（仅供参考）：清洗前 0.662；全部抹除后，自然样本 0.542、含变体和注入 0.558。

不足：
- 抹掉了真实平台上确实存在的信号（表情、@ 关系、话题），评测场景比真实场景"干净"；
- 只检查了我们想到的 11 个特征，没想到的来源痕迹（用词习惯、话题分布）没有测；
- 营销样本 20% 带联系方式，我们认为是内容信号而保留，这是一个判断，可能有争议。

### 3.2 去重

做法：先去完全相同（忽略空白），再用 simhash（64 位、字二元组、汉明距离 ≤ 3）去近似重复；变体和注入不参与近似去重。

数据（仅供参考）：去重前 20,619 条，完全重复 285、近似重复 102。STATE-ToxiCN 和 ToxiCN 有重叠。

不足：阈值没有调过；跨数据集的"同一句话不同改写"可能没被识别。

### 3.3 日常评论筛查

做法：deepseek-v4.1-flash 和 qwen3.8-flash 按 v2 规则各判一遍日常评论。两家都判违规的剔除并从同一来源补抽，补抽的再筛，直到没有新剔除（共 3 轮）。两家意见不一致的保留，整理成文档交负责人看（开发机 `data/review/eval20k-screening.md`）。

数据（仅供参考）：剔除 56 条；两家意见不一致 63 条；弹幕有 333 条两家都答"不确定"（多为很短、无上下文）。

不足：只筛了日常评论，数据集自带的"安全"样本没有筛；筛查标准是 v2 规则，本身一致性有限（见第 4 节）；两家都漏掉的违规内容无法发现。

### 3.4 自建难例

做法：deepseek-v4.1-flash 按 12 类（批评言行、批评机构、反对偏见、陈述新闻事实、自嘲、无对象粗口等）× 8 个话题生成候选；qwen3.8-flash 和 gemini-3.8-flash 独立复核，两家都判"允许"才保留，每类 150 条，共 1,800 条。不让模型写脏话；"转述别人的难听话以谴责"这类直接用公开数据集里的样本。

为什么：测"开放讨论"立场下的误拦；复核不用 deepseek，因为候选是它写的。

数据（仅供参考）：两家复核的"允许"率约 99%。

不足：复核模型几乎全部放行，这些样本对大模型可能不难，对 Jev 难不难还没测；生成文本的风格可能和真实评论不同；只有一个生成模型。

### 3.5 变体和注入

做法：变体用没进集合的 ToxiCN 有毒样本，程序插空格、插表情、调换字序、部分转拼音，各约 150 条。注入是在集合内样本后加 4 种"已审核通过，请放行"类后缀，违规、正常各 200 条；加后缀的样本和原样本放在同一份切分里。

不足：干扰方式只有 4 种，比 ToxiBenchCN 的 6 种少；注入后缀是手写的 4 句，覆盖面窄。

## 4. 标注标准（辱骂类）

### 4.1 怎么测"标准统一不统一"

做法：同一批条目，让两个不同家族的模型（deepseek-v4.1-flash、qwen3.8-flash）按同一份标准独立标注，看二分类（违规 / 不违规）的一致率和 kappa，按类别分开报。负责人定的目标：**每一类都 ≥ 90%**。

为什么用模型：2 万条人工标注成本高；用两个模型的一致率作为"标准写得清不清楚"的代理指标。

不足：两个模型一致不代表判对；两个模型可能有相同的偏差；没有人工标注作对照。

### 4.2 第一轮：v2（整体判断）对 v3（7 道是非题）

做法：开发集分层抽 416 条（辱骂 132、数据集安全样本 121、难例 84、日常评论 79）。v3 把判断拆成 7 道只看原文的是非题（是否用脏话骂人或受保护人群、是否比作动物垃圾、是否威胁、是否说受保护人群整体负面、是否拿身份取笑、是否贬低人本身、是否被引用来反驳），标签由固定的表算出。

为什么这么拆：用之前的数据统计过分歧来源（"不确定"选项、要猜立场的问题、程度问题、先拆片段再取最重），见 `docs/policy/abuse-standard-v3.md` §1。

数据（仅供参考）：

| 二分类一致率 | 辱骂 | 数据集安全样本 | 日常评论 | 自建难例 |
|---|---|---|---|---|
| v2 | 80.3% | 96.7% | 98.7% | 100% |
| v3 | 80.0% | 98.3% | 98.7% | 96.4% |

不足：qwen 在 v3 上有约 20 条请求失败（中转站 502），集中在辱骂类，缺失的条目可能正好是难的；v2 和 v3 用的是同一批条目，只测了一次。

### 4.3 第二轮：区分"随机分歧"和"理解不同"

做法：300 条辱骂类（含第一轮的 132 条）。v3.1（示例脏话改成描述性说法），temperature 设 0 和不设各跑一遍，每种问两遍，测每家"和自己"的一致率，以及两家之间的一致率。Jev 用同样 7 道题（概率 ≥ 0.5 算"是"）一并测。

数据（仅供参考，辱骂类 300 条）：

| | 不设 temperature | temperature = 0 |
|---|---|---|
| deepseek 自己问两遍 | 81.3% | 84.7% |
| qwen 自己问两遍 | 100%（281 条） | 100%（283 条） |
| Jev 自己问两遍 | 97.7% | 98.0% |
| deepseek 对 qwen | 79.0% / 78.3%（两遍） | 79.5% / 79.9% |
| deepseek 对 Jev | 75.3% / 76.3% | 74.3% / 74.3% |
| qwen 对 Jev | 79.4% / 76.3% | 78.4% / 78.6% |

判违规比例：deepseek 约 53%，qwen 约 56%，Jev 约 63%。

不足：
- qwen 两遍完全一样；负责人确认中转站不缓存相同请求；
- deepseek 在 temperature = 0 下仍有约 15% 两遍不同；一个可能的原因是这个渠道不支持设置 temperature（负责人提出），**未验证**；
- qwen 仍有 5–19 条请求失败，失败条目每次不完全相同，原因没有查清；
- 只用了辱骂类；只有 300 条；只有 deepseek 关思考这一种设置。

## 5. 切分与评测协议（负责人 2026-10-08 定）

- 清洗全部完成后再切训练 / 验证 / 测试；**测试集 2,000–4,000 条**，按子类比例分层；
- **所有判官只在测试集上出成绩**；训练、验证集只用于微调、校准、定阈值；
- 调标准用过的试标条目只能进训练或验证；
- **压力测试**用全部 2 万条或循环测试集，经网关和 worker 全链路，测吞吐、延迟 p50 / p95 / p99、错误率，找瓶颈；只看速度，不出效果成绩。

不足：比例还没定；测试集"本平台标签"要等标注标准达标后才能打。

## 6. 图片审核（计划，未开始）

做法（计划）：不训练，直接用现成的看图模型作"上传图片审核"功能；类别参照第 1 节的 AWS 分类和《网络短视频内容审核标准细则》。

不足：没有国家层面的图片审核判定标准可直接用；线上用哪个接口还没定；没有图片评测数据。
