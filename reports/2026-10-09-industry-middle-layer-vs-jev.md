# 机审与大模型之间那一层：各家主流做法 vs 我们的 Jev 快路径

日期：2026-10-09　目的：回答"预处理只是最简单的一种，各家公司主流方案是什么，和我们的 Jev 有什么差距"。
标注约定：【原文】= 读到原始来源；【二手】= 新闻/转述；【实测】= 本仓库跑出来的数字（阶段 3/4）。

## 0. 一句话结论

主流做法里，机审和大模型之间的"缓冲层"不是一个模型，而是**三件东西的组合**：① 确定性预处理（哈希/去重/词表/频控），② 一组按标签训练的小分类器（分数 + 三态阈值），③ 2025 年起新增的"策略即输入"的判官/守卫模型只处理小分类器筛出的子集。我们的 Jev 快路径对应的是 ②+③ 合并成一个"规则写成问题、输出概率"的层。差距不在架构位置，而在**三个没补上的东西**：没有按标签训练的小分类器兜底（召回靠规则问题写得好不好）、没有任何准确率数字、没有把 Jev 的判断蒸馏回廉价分类器的回路。

### 1.2 海外："策略即输入"的守卫模型，以及它们在生产里怎么被放置

- OpenAI 的 Safety Reasoner（gpt-oss-safeguard 的内部版）在生产里的放法，技术报告原话：**"(1) we use smaller and faster classifiers to determine which content to assess and (2) in some circumstances, we use Safety Reasoner asynchronously"**。并承认 **"classifiers trained on tens of thousands of high-quality labeled samples can still perform better … than gpt-oss-safeguard does when reasoning directly from the policy"**。内部多策略准确率：safeguard-120b 46.3%，内部 Safety Reasoner 52.2%，gpt-5-thinking 43.2%。【原文，[技术报告](https://cdn.openai.com/pdf/08b7dee4-8bc6-4955-a219-7793fb69090c/Technical_report__Research_Preview_of_gpt_oss_safeguard.pdf)】
- Qwen3Guard（0.6B/4B/8B）：**固定分类体系**，不吃自定义策略文本；三档 safe/controversial/unsafe，让部署方用 strict/loose 两种模式决定争议区归哪边——等价于我们的"疑似"态。英文 prompt 分类平均 F1 90.0% vs LlamaGuard4-12B 75.9%。【原文，[技术报告](https://arxiv.org/html/2510.14276v1)】
- BELLS-O（ICML 2026 workshop，28 个系统独立横评）输入侧内容审核榜：【原文，[论文](https://arxiv.org/pdf/2606.20668) Table 8】

| 系统 | 类型 | 检出率 | 误报率 | 均延迟 | 1,400 条总成本 |
|---|---|---|---|---|---|
| qwen3guard-gen-8b | 专用 | 94.5% | 0.7% | 0.19s | $0.18 |
| polyguard-qwen | 专用 | 93.5% | 0.0% | 0.17s | $0.16 |
| gpt-5.2 | 通用 | 93.8% | 0.3% | 1.04s | $0.69 |
| gpt-oss-safeguard-20b | 策略即输入 | 88.8% | 0.0% | 0.51s | $0.11 |
| gpt-oss-safeguard-120b | 策略即输入 | 87.8% | 0.0% | 0.99s | $1.18 |
| llama-guard-4-12b | 专用 | 70.5% | 3.0% | 0.29s | $0.07 |

  论文结论原话："specialized supervisors are operationally dominant: top systems match frontier LLMs on detection (≈95% vs. 94%) … while running 5–10× faster and ∼10× cheaper"；"the practical reason to prefer a specialized supervisor on content moderation is latency, not price"。
- 学术上把"策略即输入"再压回小模型的工作已经有：PAM（[arXiv 2505.19766](https://arxiv.org/abs/2505.19766)）用 LLM 按策略生成标注、训练小过滤器，声称推理比策略推理模型快 5–100×，在自定义策略基准上持平或超过。这和快手的"蒸馏回轻量模型"是同一思路。

## 2. 我们的 Jev 快路径是什么（对照口径）

- 位置：预处理（NFKC、词表、simhash、频控）之后、agent 之前；一次调用把场景下全部规则问题 + 例外问题 + 同题复述确认打包发给 Jev，取概率，policy.decide 出 通过/疑似/拦截。
- 实测【实测，阶段 3/4】：单次 0.24–0.8s，6 题约 950 入/570 出 token，≈¥0.0004/条；500 条回放 6.6% 进 agent；Jev 对同一输入确定性（3b：三种复述 100% 一致，|Δp|≤0.01），所以"确认"不是独立样本。**【更正 2026-10-09】**这条不成立：3b 的打乱臂实际没打乱、样本全是明显句子；边界句同一输入会抖 0.01–0.04，选项顺序和题面措辞各能移动约 0.04（开发文档附录 U）。
- 准确率：**无数字**。回放用的是自写句子，没有标注集；W5 的冻结集和校准还没做。

## 3. 差距清单（按对求职叙事的伤害排序）

| # | 主流有、我们没有 | 影响 | 可补程度 |
|---|---|---|---|
| G1 | **准确率/误报率数字**。易盾、BELLS-O、Qwen3Guard 全部给检出率+误报率；我们只有速度和成本 | 面试官第一问就是"你这层召回多少"；答不上等于层不存在 | W5 冻结集 + 合成反例即可出第一版数字；这是最便宜也最必须的 |
| G2 | **按标签训练的小分类器兜底**。所有国内厂商第一层都是"小模型 + 阈值"，OpenAI 也是"小快分类器决定谁进 reasoner"；我们把召回完全押在"规则问题写得对"上 | 规则问题漏写的风险类型 = 全漏；策略即输入模型在 OpenAI 自己的多策略评测上只有 46% | 不自己训；可接一个开源守卫模型（Qwen3Guard-0.6B/8B）当并行信号，判官只处理它标 controversial 的 + 新规则 |
| G3 | **蒸馏回路**（快手、PAM）：大模型/判官判过的样本 → 训小模型 → 下次不用调判官 | 我们的成本曲线不随运行下降；主流的会 | 项目范围内不做训练；但可以做"判官答案 + 人审终裁 → 导出训练集"的接口，证明数据流闭环 |
| G4 | **争议区的显式语义**。Qwen3Guard 把 controversial 当一档输出，strict/loose 由部署方选 | 我们的"疑似"是概率阈值派生的，阈值没校准 | 3c 的温度校准 + 按场景阈值表，W5 之后能做 |
| G5 | 知识库 RAG（易盾、快手）给审核模型喂案例 | 我们的 agent 只有 load_rule 和线程/账号证据，无案例库 | 可做小的"规则→案例"检索工具，但要先有标注案例 |
| G6 | 多模态在中间层（易盾/快手/阿里全是图文视频） | 我们判官层只文本（image_check 走 qwen3.8-flash，未测） | 图片先不做；文档里明说 |

主流**没有**而我们有的（面试里能反过来讲的）：
- 规则是数据不是训练：改一条 YAML 规则下一审次生效，带版本号写进审次记录；易盾是"50 条自定义规则 + 预设 Prompt"，快手是重训/蒸馏。
- 判官输出是**可校准的封闭问题概率**而不是生成文本；BELLS-O 里生成式守卫模型的延迟档（0.5–1s）我们在 0.24–0.8s 同档，但每次调用同时回答 6+ 道题。
- 整条链可恢复、幂等、可对账（阶段 2/4 已验证），这是 Pi 二开的卖点，各家宣传里完全不提工程层。

## 4. 对项目定位的修正

§2.3 原话"判官层替代机审里的小模型分类器 + 策略层"**过强**。按各家实际做法，正确说法是：判官是机审与大模型审核之间的**分流阀**——吃预处理过后的全量，用规则问题的概率决定谁可以直接处置、谁进 agent；它不替代按标签训练的小分类器（那是另一路召回信号），而是补上小分类器没有的两件事：新规则零训练生效、争议内容有概率可校准。

## 5. 没查到 / 存疑

- 数美"送审量 -75%、人工 -90%"是宣传数字，无方法说明；易盾"99.97%"同样是厂商口径。
- 快手演讲没有任何送审比例、延迟、准确率；"小模型预检大模型精查"是从蒸馏部署推出的，不是原话。
- 知乎、小红书、B 站 2025–2026 的具体分层没有一手资料（只有招聘 JD 提"结合大模型制定审核方案"）。
- BELLS-O 的延迟含 API 网络；本地部署的 Qwen3Guard 数字来自 H100 + vLLM，和我们走中转站不可直接比。
