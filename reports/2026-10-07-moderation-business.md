# 内容审核业务到底怎么运转（2026-10-07 调研，来源见文末）

> **写法说明（2026-10-08 起统一）**：本文只记录做了什么、为什么这么做、测得的数字，以及考虑不够全面的地方。文中实验数字和看法均**仅供参考**（样本、设置、标注方式都有限），不作为结论；结论由审查方判断。日期按美国纽约时间（America/New_York）。

## 1. 审什么
| 内容对象 | 审核方式 | 时效 |
|---|---|---|
| 评论、弹幕、私信、昵称、签名 | 先发后审，机审秒级，人工抽查 | 秒级 |
| 帖子、笔记、图文 | 先审后发或发后审，机审 + 命中送审策略进人审 | 小红书约 1 小时 |
| 视频 | 标题、封面、抽帧画面、ASR 音频、字幕、弹幕、评论分别过机审 | 分钟级；抖音播放到约 1 万触发人审 |
| 直播 | 截帧 + 音频 + 弹幕 + 礼物 + 昵称实时监测，处置为警告/断流/封禁 | 秒级 |
| 头像 + 昵称、帖子 + 评论 | 组合审 | – |

## 2. 三层流程（2026 年主流厂商的说法一致）
```
全部内容
 → 第一层 机审：关键词/黑白名单/频控/去重 + 小模型 + 云厂商 API
     结论三态：通过 Pass / 疑似 Review / 拦截 Block（腾讯）；RiskLevel high/medium/low/none + Label + Confidence 0–100（阿里云）
     成熟系统自动处理 95%–99%；机审:人审 ≈ 9:1；数美：传统 AI 过滤后约 3% 存疑
 → 第二层 "AI 审核员 / 审核智能体"（2025–2026 新增）：只处理疑似
     知乎 AI 审核员：从人审平台绑定了 AI 的队列里领任务，输出 放行 Auto-Pass / 释放 Release（转人工）/ 豁免 Exempt（高风险兜底）
     网易易盾 CMA：机审守速度，智能体做语义理解、规则执行、流程分发；上线前可用 5 万条做验证
     数美审核 Agent：对 3% 存疑做"认知审核"，只留 0.3%–1.5% 高疑进人工；案例送审量 15 万/日→3 万/日（−75%），识别准确率 95%
     快手明镜/安全大模型：多模态基座 + 智能体框架（规划/记忆/工具/行动）；规则库 RAG + 历史违规库 RAG；小模型预检 + 大模型精查；大模型给审核员做 ASR 总结、关键信息标识、给客户的可解释回复
     阿里云：审核大模型 + 控制台自定义"审核 agent"
 → 第三层 人审：工作台（倍速、批量）、队列按权重分发、晨会更新违禁词库和标准
     审核员一天 1,500–2,500 条视频；时效细则：涉政 ≤15 秒/条、暴力 ≤8 秒、低俗 ≤5 秒；规则 20 大类 100 小条；入职培训约一个月
     考核：出勤、量、遗漏率、二次审核通过率；质检抽查机器删除和人工判决
 → 申诉 → 复审；处置：限流 / 仅自己可见 / 下架 / 积分扣罚 / 封号
```

## 3. "疑似"是什么
机审拿不准的那一档（Review / medium / 命中送审策略）。它是人审队列的来源，也是 AI 审核员唯一处理的对象。平台核心矛盾：疑似量 × 人审时效 × 漏放风险。

## 4. 业务指标
送审量、人审量、漏放率（遗漏率）、误拦/误杀率、识别准确率、时效（秒/小时）、每条成本、审核一致性（不同审核员结论不一）、申诉翻转率、规则更新到生效的时间（云厂商改配置 2–5 分钟生效）。

## 5. 人审五大痛点（产品经理视角）
结果不一致；效率与准确难平衡；尺度把握难；系统交互差、智能识别弱；政策和标准更新滞后。

## 6. 我之前错在哪
- 把 agent 放在第一层当初筛。真实业务里第一层是毫秒级规则 + 小模型 + API，agent 放不进去。
- 把人审当"预算分配"问题包装。业务里已经有明确的槽位：机审之后、人审之前的"AI 审核员"层，任务是对疑似做认知审核并决定 放行/处置/释放到人工，并给理由。
- 把判官和 agent 混为一谈。判官（毫秒、概率、可校准）天然属于第一层或第二层入口的快速判定；大模型 agent 属于第二层的认知审核。
