# Kev-4B 微调：基线版 v0 与清洗版 v1（2026-10-09）

负责人 2026-10-09 同意训练开源判官，并要求先把 2 万条数据统一清洗。这份报告记录"基线版"（v0）和"清洗版"（v1）的做法和测试集结果；v1 见第 5 节。数字仅供参考。

## 1. 做法

| 项 | 内容 |
|---|---|
| 起点 | 发布版 `jaredpalmer/kev-4b`（delta 模式：加载它的 496 个 LoRA 张量和指针头，接着训），底座 `Qwen/Qwen3.5-4B-Base` |
| 训练数据 | `scripts/export-kev-train.ts train`，只用训练集（split-v1），共 12,694 条（sha `868c54e72839de9a`）。每条的状态和问题与快判问 Jev 时完全同形（`buildQuestions`，主视图 `text`）；只训辱骂（ABUSE-001）、营销（MARKETING-003）两题，注入防护题没训 |
| 标签 | 先用平台标签（冻结流程打的违规 / 允许）；没有平台标签时用统一后的来源标签（`eval/source-label-map-v1.json`），边界类除外；平台"不确定"的题和未重标的边界条目不训；极短条目跳过 |
| 排除 | 校准用的 1,884 行里落在训练集的 1,352 条不训，这样判官不会在训过的条目上拟合校准 |
| v0 与 v1 的区别 | v0 = 边界类已重标，Jev 挑出的可疑条目**还没**重标；v1 = 可疑条目也按冻结流程重标后的数据（12,693 条，sha `4359c7ce7883d6e9`） |
| 超参 | 1 轮，lr 2e-5，batch 2 × accum 4，bf16 权重与计算，梯度检查点；可训练参数 33.8M |
| 机器与耗时 | RTX 5060 Ti 16 GB；装了 flash-linear-attention 0.5.2 + causal-conv1d 1.7.0 后 0.395 秒 / 条，1,586 步约 84 分钟；产物 149 MB（`/hy-tmp/train/runs/kev4b-v0`，只在算力服务器） |
| 评测 | 训练完自动起 `kev.serve`，跑 `scripts/gpu/run-judge.sh`，和 Jev、发布版 Kev-4B 同一口径：在 1,884 条校准行上拟合它自己的温度（calib@847937112207），再在测试集 3,002 条上测两个视图，阈值沿用线上的（放行 0.10、处置 0.90 / 0.92） |

脚本：`scripts/gpu/train-eval.sh <data> <tag> [epochs] [lr]`（训练 → 起服务 → 评测 → 关服务）。

## 2. 区分度（测试集，`text` 视图，与阈值和校准无关）

AUROC（主问与复问平均）：

| 判官 | 辱骂 | 营销 | 注入防护 |
|---|---|---|---|
| Jev（线上） | 0.964 | 0.993 | 1.000 |
| 发布版 Kev-4B | 0.924 | 0.980 | 0.986 |
| **Kev-4B v0** | **0.961** | **0.994** | **0.996** |

只漏 1% 违规时能放行的允许条目 %（平均概率）：

| 判官 | 辱骂 | 营销 | 注入防护 |
|---|---|---|---|
| Jev | 64.0 | 94.0 | 99.9 |
| 发布版 Kev-4B | 44.8 | 76.8 | 95.4 |
| **Kev-4B v0** | **75.0** | **88.6** | **97.1** |

v0 主问与复问选同一项：辱骂 99.3%、营销 99.7%、注入 100%；"无法判断"平均概率 0。`text_strip` 视图和 `text` 差别在 0.001 以内（辱骂 0.961、营销 0.993、注入 0.996）。

注入防护题没有训练，AUROC 也从 0.986 变成了 0.996。

## 3. 分流（用它自己的校准 + 线上阈值，`text` 视图）

| 判官 | 违规被自动放行 | 违规自动处置 | 违规转 agent | 允许自动放行 | 允许被自动处置 | 允许转 agent |
|---|---|---|---|---|---|---|
| Jev | 2.2% | 33.2% | 64.5% | 70.6% | 0.3% | 29.0% |
| 发布版 Kev-4B | 9.4% | 0.5% | 90.1% | 68.9% | 0 | 31.1% |
| **Kev-4B v0** | **1.1%** | **43.7%** | **55.2%** | **56.5%** | **0.8%** | **42.6%** |

（违规 812、允许 2,042、平台不确定 140、无标签 8。）

分组（违规被自动放行 % / 允许被自动处置 %，发布版 → v0）：

| 分组 | 违规 n / 允许 n | 违规被自动放行 | 允许被自动处置 | 允许自动放行 |
|---|---|---|---|---|
| 难负例 | 6 / 259 | 33.3 → **66.7**（6 条里 4 条） | 0 → 0 | 78.8 → 83.0 |
| 日常 | 25 / 867 | 20.0 → 4.0 | 0 → 0 | 81.7 → 81.3 |
| 辱骂 | 384 / 275 | 6.0 → 0.5 | 0 → 2.2 | 23.6 → 4.4 |
| 数据集正常 | 38 / 533 | 10.5 → 5.3 | 0 → 0 | 72.0 → 40.2 |
| 对抗 | 52 / 36 | 11.5 → 0 | 0 → 19.4 | 27.8 → 0 |
| 营销 | 295 / 58 | 11.9 → 0 | 0 → 8.6 | 48.3 → 6.9 |
| 注入 | 12 / 14 | 8.3 → 0 | 0 → 0 | 57.1 → 28.6 |

时延：本机 kev.serve，并发 16，成功请求 p50 / p95 = 1,839 / 1,971 ms（Jev 远程 436 / 498 ms，不是同一条件）。

## 4. 不足

1. **标签同源**：训练标签约 1,000 条 / 题来自平台冻结流程，测试集也用同一流程打标。v0 学的是这套标准，和没见过这套标准的 Jev、发布版 Kev-4B 比，条件不对等。
2. **阈值沿用 Jev 的**（开发计划问题 10）：v0 的自动处置多了，"允许被自动处置" 0.8%（对抗组允许 36 条里 7 条、营销组 58 条里 5 条、辱骂组 275 条里 6 条），比 Jev 的 0.3% 高；数据集正常组的自动放行从 72.0% 降到 40.2%。没按 v0 在验证集上重定阈值。
3. **难负例组违规只有 6 条**，6 条里 4 条被自动放行，样本太小，看不出方向。
4. **v0 和 v1 的 batch 不同**：v1 用 batch 4 × accum 2（负责人 10-09："下一次你清洗就换一下"），有效 batch 相同（8），但步内样本组合不同；两版差在约 0.005 AUROC 以内时，分不清是数据还是 batch 的影响。
5. 只训 1 轮、1 个 lr、1 个随机种子，没有重复。
6. 微调后的权重只在算力服务器，没做发布 / 部署；线上仍是 Jev。

## 5. v1（清洗版）

**和 v0 的差别**：训练数据换成 Jev 挑出的 816 条可疑条目按冻结流程重标后的版本（12,693 条，sha `4359c7ce7883d6e9`；重标结果见 `docs/eval-dataset-plan.md` 4.3）；batch 4 × accum 2（负责人 10-09："下一次你清洗就换一下"），有效 batch 仍是 8、步数仍是 1,586；其余设置相同。batch 4 没有显存溢出，0.293 秒 / 条，训练约 62 分钟（v0 0.395 秒 / 条）。训练损失全程平均 0.152（v0 0.193）。评测同第 1 节，它自己的校准 calib@362a92558d64。

区分度（`text` 视图，AUROC / 只漏 1% 违规时放行的允许条目 %）：

| 判官 | 辱骂 | 营销 | 注入防护 |
|---|---|---|---|
| Jev | 0.964 / 64.0 | 0.993 / 94.0 | 1.000 / 99.9 |
| 发布版 Kev-4B | 0.924 / 44.8 | 0.980 / 76.8 | 0.986 / 95.4 |
| Kev-4B v0 | 0.961 / 75.0 | 0.994 / 88.6 | 0.996 / 97.1 |
| **Kev-4B v1** | **0.964 / 72.8** | **0.999 / 97.4** | **0.996 / 98.2** |

v1 主问与复问选同一项：99.2% / 99.8% / 100%；"无法判断"平均概率 0。`text_strip` 视图：0.964 / 0.997 / 0.996。

分流（它自己的校准 + 线上阈值）：

| 判官 | 违规被自动放行 | 违规自动处置 | 违规转 agent | 允许自动放行 | 允许被自动处置 | 允许转 agent |
|---|---|---|---|---|---|---|
| Jev | 2.2% | 33.2% | 64.5% | 70.6% | 0.3% | 29.0% |
| Kev-4B v0 | 1.1% | 43.7% | 55.2% | 56.5% | 0.8% | 42.6% |
| **Kev-4B v1** | **2.0%** | **44.4%** | **53.7%** | **68.2%** | **0.3%** | **31.5%** |

分组（v0 → v1）：

| 分组 | 违规 n / 允许 n | 违规被自动放行 | 允许被自动处置 | 允许自动放行 |
|---|---|---|---|---|
| 难负例 | 6 / 259 | 66.7 → 66.7 | 0 → 0 | 83.0 → 89.2 |
| 日常 | 25 / 867 | 4.0 → 20.0 | 0 → 0 | 81.3 → 88.9 |
| 辱骂 | 384 / 275 | 0.5 → 0.5 | 2.2 → 0.4 | 4.4 → 8.4 |
| 数据集正常 | 38 / 533 | 5.3 → 10.5 | 0 → 2.6 | 40.2 → 61.4 |
| 对抗 | 52 / 36 | 0 → 0 | 19.4 → 16.7 | 0 → 0 |
| 营销 | 295 / 58 | 0 → 0.3 | 8.6 → 0 | 6.9 → 56.9 |
| 注入 | 12 / 14 | 0 → 0 | 0 → 0 | 28.6 → 50.0 |

时延：并发 16，成功请求 p50 / p95 = 1,867 / 2,067 ms。

**不足（在第 4 节之外）**：

1. v1 的重标条目和测试集用同一冻结流程，第 4 节第 1 条的"标签同源"在 v1 上更重；v1 比 v0 好的部分里，有多少来自"更接近测试集的打标口味"，分不出来。
2. v0 → v1 同时改了数据和 batch（第 4 节第 4 条）；辱骂 AUROC 差 0.003，在这个范围内。
3. 对抗组允许 36 条里 6 条被自动处置；日常组违规 25 条里 5 条、数据集正常组违规 38 条里 4 条被自动放行；这几组样本小。
4. 没有在不经平台流程打标的公开测试集上测（例如各来源数据集自带的测试集），也没有和其他公开安全判官比。

## 复现

```bash
# 开发机：导出训练记录（带原文，只在服务器）
EXCLUDE=data/calib/platform-input.jsonl node --experimental-strip-types scripts/export-kev-train.ts train data/train/train-v0.jsonl
# 算力服务器（仓库副本 /hy-tmp/pma）：
bash scripts/gpu/train-eval.sh /hy-tmp/train/train-v0.jsonl kev4b-v0
BATCH=4 ACCUM=2 bash scripts/gpu/train-eval.sh /hy-tmp/train/train-v1.jsonl kev4b-v1
# 结果：data/eval/test-v1-kev4b-{v0,v1}/{separation,score}-{text,text_strip}.json、routing-check.out
```
