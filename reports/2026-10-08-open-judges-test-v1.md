# 第 ④ 阶段：开源判官在测试集 split-v1 上（2026-10-08）

> **写法说明（2026-10-08 起统一）**：本文只记录做了什么、为什么这么做、测得的数字，以及考虑不够全面的地方。文中实验数字和看法均**仅供参考**（样本、设置、标注方式都有限），不作为结论；结论由审查方判断。日期按美国纽约时间（America/New_York）。

## 1. 做了什么

负责人 2026-10-08 提供了一台按小时计费的算力服务器（RTX 5060 Ti 16 GB、8 核、64 GB 内存、数据盘 100 GB），让试开源判官。做法和 Jev 完全同一口径（`reports/2026-10-08-test-v1-fastpath-jev.md`）：

| 项 | 值 |
|---|---|
| 判官 | Laya（`convaiinnovations/laya`，`multilingual`，laya-serve）；Kev-4B（`jaredpalmer/kev-4b`，bf16，kev.serve）；Kev-0.8B（`jaredpalmer/kev-0.8b`）。两者都实现 Jev 的 `/v1/systemone` 协议，所以评测脚本不改，只把 `JEV_BASE_URL` 指到本机端口 |
| 没测的 | Kev-9B（bf16 权重约 18 GB，16 GB 显存放不下，kev.serve 不支持量化）、Kev-27B |
| 流程 | `scripts/gpu/run-judge.sh`：① 在 1,884 条开发行（平台标签）上问快判同一组问题；② 按题拟合温度（每个判官自己的校准）；③ 测试集 3,002 条，主视图 `text` 和全抹除对照 `text_strip`；④ 用自己的校准走 `policy.decide` 分流打分；⑤ 不依赖阈值和校准的区分度（`eval-test.ts separation`，本次新增） |
| 标签 | 测试集平台标签（冻结流程）；"不确定"不进二分类 |
| 服务器准备 | `scripts/gpu/setup-mirrors.sh`：apt、pip/uv、npm、HuggingFace 换国内镜像 |

**为什么加区分度（separation）**：Laya 和 Kev-0.8B 用自己拟合的校准分流时全部进 agent，分流百分比无法比较判官本身。区分度只看原始答案里"违规"概率能否把平台标签的违规 / 允许分开（AUROC），加上主问与同次复问选同一选项的比例、"无法判断"选项分到的概率、以及"放行线定在只漏 1% 违规时能放行多少允许条目"。温度校准基本不改变排序，所以这几项和校准无关。

## 3. 用自己的校准、线上阈值分流【实测，主视图，平台标签 ALL：违规 812 / 允许 2,042】

| 判官 | 违规被自动放行 | 违规自动处置 | 违规转 agent | 允许自动放行 | 允许被自动处置 | 允许转 agent | 成功请求时延 p50 / p95 |
|---|---|---|---|---|---|---|---|
| Jev | 2.2% | 33.2% | 64.5% | 70.6% | 0.3% | 29.0% | 436 / 498 ms（远程 API） |
| Kev-4B | 9.4% | 0.5% | 90.1% | 68.9% | 0.0% | 31.1% | 1,852 / 2,145 ms（本机，并发 16） |
| Kev-0.8B | 0 | 0 | 100% | 0 | 0 | 100% | 371 / 418 ms |
| Laya | 0 | 0 | 100% | 0 | 0 | 100% | 706 / 759 ms |

请求：每个判官每个视图 3,002 次，0 失败（Jev 那次有 1 次失败后重试成功）。

分组里值得看的几格（违规被自动放行）：难负例组 Jev 16.7%（6 条里 1 条）、Kev-4B 33.3%（2 条）；对抗组 Jev 1.9%、Kev-4B 11.5%；注入组 Jev 0、Kev-4B 8.3%。

**拟合出的温度**：

| 判官 | 辱骂 | 营销 | 注入检查 |
|---|---|---|---|
| Jev（线上） | 1.379 | 1.251 | 0.352 |
| Kev-4B | 0.697 | 0.731 | 2.867 |
| Kev-0.8B | 2.139 | 7.987 | 4.447 |
| Laya | 5.149 | 7.987 | 7.987 |

7.987 是拟合搜索范围的上界，即拟合时一直在把概率往平均压。温度大到这个程度时，校准后的违规概率几乎都落在 0.10–0.90 之间，所以 Laya、Kev-0.8B 全部进 agent。

## 4. 发现的问题（已记入开发计划）

1. **阈值是按 Jev 定的**：放行线 0.10、处置线 0.90 / 0.92 用到 Kev-4B 上，违规被自动放行 9.4%（Jev 2.2%），自动处置几乎没有。换判官时阈值不能沿用，需要按该判官在验证集上重定；目前代码里阈值属于规则，不随判官变。
2. **温度拟合碰到上界**：Laya 和 Kev-0.8B 有题拟合到搜索上界，说明单一温度不足以校准它们（例如"无法判断"一项分走的概率太多）。
3. **Laya 对选项顺序敏感**：主问与复问常常选不同选项；它的 multilingual 版本不是为中文审核训练的。
4. 开源判官的时延是本机单卡、并发 16 下测的，不能直接与远程 API 比较。

## 5. 考虑不够全面的地方

- 平台标签本身由 deepseek、qwen、gemini 三个模型按冻结流程给出，不是人工标注；判官和这几个模型"想法相近"也会让 AUROC 偏高。
- 只测了一次；没有置信区间；注入检查题违规只有 27 条。
- Kev 的服务端自带一个注册温度（4B 为 2.41），本文的校准是在它之上再拟合一层。
- Kev-9B / 27B 没测（显存不够）；没有在开源判官上做 agent 阶段或端到端。
- 没做微调（开发计划第 7 节 "Kev 微调" 暂缓）。

## 6. 复现

```bash
# 算力服务器上：
bash scripts/gpu/setup-mirrors.sh
# 起判官服务（laya-serve 端口 8010 / kev.serve 端口 8009），然后：
bash scripts/gpu/run-judge.sh 8010 multilingual
bash scripts/gpu/run-judge.sh 8009 kev-latest               # Kev-4B
bash scripts/gpu/run-judge.sh 8009 kev-latest kev-0.8b      # KEV_RUN=jaredpalmer/kev-0.8b 起服务后
# Jev 的区分度（开发机）：
node --experimental-strip-types scripts/eval-test.ts separation data/eval/test-v1-jev text
```

运行清单（判官、规则版本、切分清单 sha、评测集 sha、起止、成败、输出 sha）在服务器 `data/eval/test-v1-<判官>/manifest-*.json`；平台标签文件（只有 id 和标签）为评分临时拷到了算力服务器。

**过程中的问题**：Kev-4B 运行中途替换了 `run-judge.sh`（bash 按偏移读脚本），收集已完成后打分一步报错 `TAG: unbound variable`；打分、区分度、分流检查随后手动用同样的命令补跑。以后不在运行中覆盖正在执行的脚本。
