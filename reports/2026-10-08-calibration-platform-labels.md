# 用平台标签做快判校准（2026-10-08）

> **写法说明（2026-10-08 起统一）**：本文只记录做了什么、为什么这么做、测得的数字，以及考虑不够全面的地方。文中实验数字和看法均**仅供参考**（样本、设置、标注方式都有限），不作为结论；结论由审查方判断。日期按美国纽约时间（America/New_York）。

## 1. 做了什么

按负责人 10-08 的决定（`docs/dev-plan-2026-10-08.md` §0.1 第 2 条），校准改用本平台的模型辅助标签，替换此前用 COLD / ChineseHarm 公开标签的尝试（`reports/2026-10-08-calibration-with-public-labels.md`，未采用）。

| 步骤 | 做法 |
|---|---|
| 标签 | 冻结标准辱骂 v4.3、营销 v2、注入检查 v1（`docs/policy/labeling-standard-v4.md`），两模型各 3 次取多数、分歧由 gemini 第三票、仍不一致的由负责人委托裁定；"不确定"不进拟合 |
| 样本 | 开发集里所有做过平台标注的条目，去掉案例池 v1 的 40 条公开样本（`data/cases/pool-v1-exclude.txt`）；共 1,884 条（`scripts/build-calib-platform.ts`，输入文件 sha `2925a08ea605edca`） |
| 文本 | 评测主视图（E5，线上判官看到的同一形式，mv-2） |
| 判官作答 | `fit-calib.ts collect`：Jev（jev-latest）按快判的问法作答，记录主问和同次复问的完整概率；1,884 条全部成功，用时 54 秒 |
| 拟合 | `fit-calib.ts fit`：每题按 id 哈希留出 20%，其余拟合温度 T |
| 分流检查 | `scripts/calib-routing-check.ts`：只用留出的 20%（383 条），按线上同一校准器和 `policy.decide` 走一遍，和不校准（identity）对比 |

## 4. 采用情况

校准文件放入 `calib/jev-latest/`（运行时默认 `CALIB_DIR=calib`），版本 `calib@e57aa6b1ae15`，绑定规则版本 `rules@0c46158a17ee`；规则改了以后这些文件不再匹配，相应的题会按"缺校准"转人工，需要重新拟合。A/C 对比使用这份校准。

契约测试（`pnpm run contract`）在校准后仍是 5/7，c1、c2 期望"拦截"、实际"疑似"，和不校准时相同。

## 5. 考虑不够全面的地方

- 标签是模型辅助标签，不是人工金标准；"第三票"偏向允许（标准文档 5d）会让拟合偏向低估违规。
- 留出样本和拟合样本来自同一批开发集试标样本（按 id 哈希分开），不是另一份独立数据；用于调标注提示词的样本也在其中。
- 只拟合了温度一个参数，没有按场景、文本长度、来源分桶；ECE 在辱骂题上没有下降。
- 拦截线 0.90、放行线 0.10 没有随校准调整；转 agent 的比例（不违规组 42%）主要由这两条线决定，没有测不同阈值。
- 注入检查题只有模板化后缀的正样本，T = 0.35 让它更"自信"，在难样本上的表现未知。
